## Purpose

Persist concrete outputs without inventing a second run state, report state, or publication state. This skill answers: which files exist, what semantic role each file has, what immutable identity/checksum was observed, and where the durable copy lives.

## Activation

Use for saving/exporting an existing tool, checker, hook, eval, skill, agent, or experiment artifact. Experiment execution itself routes to `experiment-lifecycle`; reader interpretation routes to `report-writing`; HTML generation routes to `html-output`; result-branch publication remains an explicit tool operation.

## Contract

For every selected artifact that actually exists, record enough information to identify it without relying on its filename alone:

- stable run/result identity or parent evidence reference;
- repository-relative or artifact-root-relative path;
- semantic role, such as raw measurement, case output, diagnostic log, summary data, rendered view, or execution notebook;
- content checksum or equivalent immutable content identity;
- producer/source reference when needed to interpret the artifact;
- write status/readback proving that the durable destination contains the intended bytes.

Do not overwrite an existing different artifact at the same identity. Replays with identical bytes may be recognized as idempotent; conflicting bytes require a new identity or an explicit owner decision.

## No fixed artifact inventory

The manifest enumerates files that were actually generated by the selected producer. It must not require a universal set such as `summary.json`, `cases.jsonl`, notebook, startup log, plots, or per-case files when that producer never creates them.

Producer-specific protocols may declare required outputs. Those requirements belong to that producer/protocol and are checked against the actual run. Absence of an artifact that was never selected or generated is not materialized as a synthetic `missing`, `not_requested`, or limitation record.

For experiment results, the reproducibility core—source, effective config, command/protocol, relevant environment, terminal status, and references to actual artifacts—is owned by `experiment-lifecycle`. This skill does not duplicate those fields into a second save-experiment state machine.

## Reports and publication

A raw artifact write does not imply a reader report. Add `report-writing` only when the request requires synthesis, claims, limitations, or decisions.

A durable local result does not imply a Git branch or remote publication. For experiments, publication is an explicit operation such as:

`python3 tools/experiments/publish_result_branch.py --result-dir experiments/<topic>/result/<run_name> --branch experiment-results/<topic>`

Add remote push only when authorized by the run/publication plan. For agent-runtime report archives, use the existing `runtime_log_archive_git.py` owner rather than a new result wrapper.

## Completion

Completion requires successful readback for the selected files and no unresolved overwrite conflict. It does not require tokens for optional operations that did not run and does not require a fixed number of manifest entries.
